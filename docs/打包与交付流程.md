# 打包与交付流程

只在用户明确说“打包”时才打 jar。

1. 前端：停掉 vite，`cd web && npm run build`（生成 web/dist，web/public 下的静态页如掌控板也在这一步进 dist）。
2. 后端：先删 `ittools-app/target/classes/static` 和 `ittools-app/target/*.jar`（不删的话历次构建的旧前端文件会一直累积进 jar），
   再 `mvn -o install -DskipTests -Dskip.frontend.build=true`（不加 skip 会触发 npm ci 冲掉 node_modules）。
   产物：`ittools-app/target/ittools-app-0.1.0-SNAPSHOT.jar`。
3. **同步到交付包**（每次重新打包都要做）`E:\ITtools\交付包\ITtools\`：
   - 把交付包里现有的 `ittools.jar` 复制到 `backup\ittools_v<旧版本号>.jar`；
   - 新 jar 复制为 `ittools.jar`（文件名固定，start.bat 用它）；
   - 在 `版本记录.md` 表格最上面追加一行：版本号 `vYYYYMMDD`（同日第二次起 `vYYYYMMDD-2`）、日期、改动内容。
4. 重打 `ITtools.zip`：旧 zip 先移到 `backup\ITtools_v<旧版本号>.zip`，再把 ittools.jar、start.bat、部署说明.txt、版本记录.md、backup.ps1、open-firewall-8300.bat、使用说明书.docx、学生机脚本\ 以及空的 backup\、data\storage\ 打进新 zip（用 Python zipfile，保证中文文件名为 UTF-8）。
5. **发布 GitHub Release**：代码先提交推送并合并进 `main`，在 `main` 上打 tag（与交付包版本号相同，如 `v20261123`），
   `gh release create <tag> ITtools.zip ittools.jar --title "ITtools <tag>" --notes-file <说明>`，
   说明里写版本记录那一行、部署/升级要点和两个文件的 SHA-256。不要把 jar、zip 提交进仓库。

## 附：功能开关
管理员端「系统 → 功能开关」按学生 / 教师分别开关菜单功能。新增菜单功能时，要同步在
`FeatureCatalog.java`（功能清单 + 独占接口前缀）、路由 `meta.feature`、布局菜单里登记。

## 更新 Word 版说明书

`docs/使用说明书.md` 是文字来源，改完后重新生成 `docs/ITtools使用说明书.docx`：

1. 在任意临时目录 `npm install docx@9`，再运行 `node <项目>/scripts/md2docx.js docs/使用说明书.md 输出.docx "2026 年 11 月"`（最后一个参数是封面日期）。
2. 用 Word 打开生成的文件，在目录上右键“更新域 → 更新整个目录”后保存（或用 Word COM 调 `TablesOfContents.Update()`），目录页码才会正确。
3. 复制到 `docs/` 和交付包，重打 `ITtools.zip`。

## 掌控板助手（学生机）

`tools/mpagent/mpagent.py` 改动后按 `tools/mpagent/README.md` 重新打包，`ITtools掌控板助手.exe` 放进交付包 `学生机脚本\`（和“配置学生机浏览器.bat”放一起），再重打 `ITtools.zip`。
